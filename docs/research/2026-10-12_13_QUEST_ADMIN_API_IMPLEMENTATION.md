# Quest Admin API contract

All routes require verified Quest permission. No browser Supabase writes.

- GET `/api/quests?search=&id=&type=&minLevel=&maxLevel=&page=1&pageSize=25`: `{items: QuestRecord[],total,page,pageSize,canWrite}`.
- GET `/api/quests/:id`: `QuestDetail` below.
- PATCH `/api/quests/:id`: `{expectedRevision,reason,requestId,patch:{quest?: changedFields,requirements?:{insert?,update?:[{id,changes}],deleteIds?},awards?: same,prerequisites?: same}}`. IDs/qid immutable. Omission means unchanged. No replacement arrays.
- GET `/api/quests/lookups?kind=npc|monster|item|equipment|pet|quest|loop|class&search=&page=&pageSize=`: `{items:[{id,name,table}],total,page,pageSize}`.
- GET/PATCH `/api/quests/loops/:id`: independent shared-loop revision; PATCH `{expectedRevision,expectedAffectedCount,confirmShared:true,reason,requestId,patch:changedFields}`.
- GET `/api/quests/access`: `{canRead:true,canWrite,role}`.

`QuestDetail`: `{questId,revision,quest,requirements,awards,prerequisites,loopRef,warnings:string[],activeUse:{activeQuests,completedHistory,activeLoops},canWrite,activation:{databaseSaved,serverReloadRequired:true,clientRefreshRequired:true,mode:"database-only",flashCatalogBlocked:true,clientCatalogPublicationRequired:true}}`.
Raw rows use exact snake_case columns, IDs are int4 numbers, every PostgreSQL numeric is a decimal **string** or null. No null/sentinel/script normalization. Shared loop shape: `{loop,revision,affectedQuestCount,warnings,canWrite,activation}`. PATCH returns canonical detail with databaseSaved=true. Errors `{error:{code,message,issues?}}`, 401/403 auth, 404 absent, 409 optimistic/idempotency/active-use conflict, 413 body >128KiB, 422 malformed/unsafe edits, 503 unavailable. Actor comes exclusively from verified server identity. No restart/activation is performed. Required restart/client refresh flags are **necessary, NOT sufficient**: consistent gameplay activation is BLOCKED until verified client catalog publication/index reconstruction exists. Relog is not an activation solution.

Persisted active-use guards reject semantic root/child edits (except name/info/dialogue/color), and shared-loop semantic changes while active. These read-only counts cannot see unsaved online/cache progress; current backend cache is deliberately left unchanged. No preservation claim for later activation without an offline/publication protocol.
